Compare Daisho runs without writing plotting code

Daisho Run Viewer takes a folder of Daisho variational outputs and sorts them into cases, runs and time windows, using the settings stored inside each file. Then it draws them: a table of every run and time; the 3D view of W and reflectivity, which can be saved as a turning, time-stepping movie; plan views with N–S and E–W slices, QFLAG included; every case on one map; and the run comparisons (cost, convergence, wind coverage, W profiles, the storm through time).

Files are read here in your browser. Nothing is uploaded, and reloading the page forgets them.

Get your runs onto the page

  1. Run Daisho as usual

    Keep the TOML each run used, and save what Daisho printed while it ran (your Slurm .log, for example). The log is optional, but it is where run time and the convergence curve come from.

  2. Stamp each output

    A Daisho output does not record its settings, so the page could not tell a ROI 1.5 run from a ROI 2.25 run. stamp_daisho.py (below) writes a copy of each output into ./daisho_web with the TOML and the log's numbers stored inside. Your original files are only read. It does a dry run unless you add --write.

    python stamp_daisho.py var_20220807_time_1.nc --toml var_20220807_time_1.toml --log job_1.log --case 20220807 --time time_1 --write

    For every time window of a case at once:

    for t in 1 2 3 4 5 6 7; do
  python stamp_daisho.py out/var_20220807_time_${t}.nc --toml tomls/var_20220807_time_${t}.toml --log logs/job_${t}.log --case 20220807 --time time_${t} --write
done

    Without --case the case is the date of the scan, so set it when two cells share a day (20220917_1 and 20220917_2). Without --time the time window is the scan's start time.

  3. Load the folder

    Copy the daisho_web folder to your computer, then choose it here. Files from different runs, cases and times can all go in one folder; their names do not matter.

stamp_daisho.py

Copy it and save it as stamp_daisho.py. It needs Python 3 with numpy and netCDF4 (conda install -c conda-forge netcdf4).


      
    


    

      
What the stamp stores

      
    
        
  • The TOML text. Files with the same settings are one run. The domain position and size, the metadata block and the iteration cap are left out of that comparison, since they change from case to case.
    • 
        
  • Case, time window and a run tag. The tag is only a label; it never decides grouping.
    • 
        
  • From the log: CG iterations, whether it converged, the final residual, solve time, job time (when the log has start: and end: lines), and the residual at each logged CG step.

How files are sorted

    
    
      
  • Case and time window come from the stamp (daisho_case, daisho_time_window). Files without a stamp are sorted by the date and start time of the scan.
    • 
      
  • Run = every file whose stored TOML has the same settings. File names and run tags are never used to group.
    • 
      
  • Ignored when comparing settings: the domain position and size (grid.springsteel.i/j/k min, max and cells, which change with each case and time window), [grid.metadata], and max_inner_iterations. The grid spacing (max − min ÷ cells) is compared instead.
    • 
      
  • Run labels list only the settings that differ between the runs you loaded. ROI in output cells = ROI factor ÷ mubar.
